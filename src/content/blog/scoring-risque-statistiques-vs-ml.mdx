La régression logistique et les GLM restent dominants dans beaucoup d'équipes de risque, et ce
n'est pas de la nostalgie. Les coefficients se lisent directement, sans outil d'explicabilité
additionnel. Le comportement du modèle est monotone et connu à l'avance, ce qui facilite l'audit.
Et sur un nombre limité de variables et un jeu de données de taille modeste, le risque de
surapprentissage reste plus contenu qu'avec un modèle plus flexible.

```python
from sklearn.linear_model import LogisticRegression
import xgboost as xgb
from sklearn.metrics import roc_auc_score

logit = LogisticRegression(max_iter=1000).fit(X_train, y_train)
xgb_model = xgb.XGBClassifier(max_depth=5, n_estimators=200).fit(X_train, y_train)

print("Logit AUC:", roc_auc_score(y_test, logit.predict_proba(X_test)[:, 1]))
print("XGBoost AUC:", roc_auc_score(y_test, xgb_model.predict_proba(X_test)[:, 1]))
```

Sur des données avec des interactions non linéaires — fréquent en crédit ou en tarification
assurantielle — un modèle à base d'arbres capture souvent un gain d'AUC réel, parfois de
quelques points, parfois nettement plus selon la richesse des interactions présentes.

## L'approche challenger, plutôt que le choix binaire

Beaucoup d'équipes évitent de trancher directement en gardant le GLM comme modèle de
production officiel, utilisé pour les décisions, tout en faisant tourner un modèle ML en
parallèle sur les mêmes données. Si l'écart de performance reste significatif et stable dans
le temps, ça justifie d'investir dans l'explicabilité du modèle ML — SHAP, par exemple — pour
le faire progressivement remplacer le GLM, plutôt que de basculer d'un coup sans historique de
comparaison.

La question à se poser reste toujours la même dans ces projets : le gain de performance
couvre-t-il le coût de complexité et de gouvernance supplémentaire. Sur un segment de risque
stable et déjà bien compris, un GLM bien calibré peut rester le meilleur choix, même face à un
modèle plus précis de quelques points.
