Un notebook qui contient `AWS_SECRET_KEY = "AKIA..."` en clair fonctionne très bien jusqu'au
jour où ce notebook est poussé sur un dépôt public par erreur, ou partagé avec un collègue qui
n'aurait jamais dû avoir cet accès. Séparer secrets et code n'est pas une bonne pratique
optionnelle, c'est une des rares choses en MLOps qui a un vrai coût de sécurité si elle est
négligée.

## Le principe de base : jamais de secret dans le code versionné

```python
# À éviter absolument
API_KEY = "sk-a1b2c3d4e5f6..."

# À privilégier
import os
API_KEY = os.environ["API_KEY"]
```

Le code lit une variable d'environnement ; la valeur réelle est injectée au moment de
l'exécution, jamais stockée dans le dépôt. Un fichier `.env` local (ajouté au `.gitignore`)
couvre le développement ; en production, le secret vient du gestionnaire de secrets de la
plateforme (AWS Secrets Manager, GCP Secret Manager, HashiCorp Vault).

## Ce qui distingue secret et configuration

Tout ne mérite pas le même niveau de protection. Une clé d'API ou un mot de passe est un
secret : accès restreint, rotation périodique, jamais loggé. Un chemin de fichier ou un nombre
de workers est de la configuration : peut être versionné sans risque, dans un fichier YAML ou
des variables d'environnement non sensibles. Mélanger les deux dans un même fichier de
configuration finit par rendre difficile de savoir ce qui doit rester confidentiel.

## Le piège du log accidentel

```python
logging.info(f"Connexion à la base avec les paramètres : {config}")
```

Si `config` contient un mot de passe, il se retrouve dans les logs — souvent moins protégés que
le code source lui-même, et parfois envoyés vers des outils tiers de monitoring. Filtrer
explicitement les clés sensibles avant de logger un objet de configuration évite ce genre de
fuite, qui arrive plus souvent qu'on ne le pense.

## La rotation, l'étape qu'on oublie

Stocker un secret correctement ne suffit pas s'il n'est jamais changé après une fuite suspectée
ou le départ d'un collaborateur qui y avait accès. Un gestionnaire de secrets managé permet
généralement de programmer une rotation automatique — une clé d'API qui n'a jamais changé depuis
trois ans, même bien stockée, reste un risque qui s'accumule silencieusement.
