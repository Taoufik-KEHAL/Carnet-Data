Random Forest entraîne de nombreux arbres indépendamment, sur des sous-échantillons aléatoires
des données, puis moyenne leurs prédictions — chaque arbre vote séparément. XGBoost construit
ses arbres de façon séquentielle : chaque nouvel arbre corrige les erreurs des arbres
précédents. L'apprentissage est cumulatif d'un côté, indépendant de l'autre, et ça change
beaucoup de choses en pratique.

Random Forest reste préférable quand le jeu de données est petit à moyen et que le risque de
surapprentissage est une vraie préoccupation, quand on veut un modèle robuste avec peu de
réglage d'hyperparamètres, ou quand l'entraînement doit être facilement parallélisable.
XGBoost prend l'avantage quand la performance brute prime et qu'on peut investir du temps dans
le réglage — taux d'apprentissage, profondeur, régularisation —, sur des jeux de données de
taille moyenne à grande, ou quand il faut gérer nativement les valeurs manquantes.

```python
import xgboost as xgb
from sklearn.ensemble import RandomForestClassifier

# Random Forest — robuste, peu de réglage
rf = RandomForestClassifier(n_estimators=200, max_depth=10)

# XGBoost — plus de contrôle, plus de performance potentielle
xgb_model = xgb.XGBClassifier(
    n_estimators=300,
    learning_rate=0.05,
    max_depth=6,
    reg_lambda=1.0,
)
```

Dans la pratique, tester les deux coûte peu de temps et donne une réponse empirique bien plus
fiable que n'importe quelle règle générale lue dans un article. La question à se poser n'est
pas "lequel est meilleur" mais "lequel est meilleur pour ce jeu de données précis, avec ces
contraintes précises" — et souvent, seul un test réel sur les données en question tranche
vraiment.
