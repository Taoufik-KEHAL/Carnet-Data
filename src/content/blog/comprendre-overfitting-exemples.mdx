```python
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error

for degre in [1, 3, 15]:
    poly = PolynomialFeatures(degree=degre)
    X_train_poly = poly.fit_transform(X_train)
    X_test_poly = poly.transform(X_test)

    model = LinearRegression().fit(X_train_poly, y_train)
    erreur_train = mean_squared_error(y_train, model.predict(X_train_poly))
    erreur_test = mean_squared_error(y_test, model.predict(X_test_poly))

    print(f"degré {degre} — train: {erreur_train:.3f}, test: {erreur_test:.3f}")
```

Avec un degré 1, les deux erreurs restent proches mais élevées — sous-apprentissage classique.
Avec un degré 15, l'erreur d'entraînement s'effondre presque à zéro, le modèle passant par
quasiment tous les points d'entraînement, pendant que l'erreur de test explose. Il n'a rien
appris de la tendance sous-jacente, il a mémorisé le bruit propre à cet échantillon précis.

Le signal le plus fiable n'est pas "l'erreur d'entraînement est basse", c'est l'écart entre
erreur d'entraînement et erreur de test. Un petit écart avec une erreur de test acceptable est
sain. Un grand écart, même avec une erreur de test correcte dans l'absolu, signale un modèle
fragile qui va mal généraliser dès que les données réelles s'écartent un peu de celles vues à
l'entraînement.

Trois causes reviennent le plus souvent en pratique : trop de paramètres pour trop peu de
données (arbres profonds, réseaux larges, polynômes de haut degré qui s'ajustent au bruit sur
un petit jeu de données), une fuite d'information où une feature est calculée à partir de
données qui ne seraient pas disponibles au moment réel de la prédiction, et une validation
croisée absente ou mal faite qui masque une variance que révélerait un k-fold.

Les leviers de correction restent classiques : réduire la capacité du modèle, ajouter de la
régularisation (L1/L2, profondeur limitée, early stopping), ou tout simplement récolter plus de
données. Aucun n'est universel — le bon réflexe reste de toujours comparer erreur
d'entraînement et erreur de validation avant de qualifier un modèle de "performant".
