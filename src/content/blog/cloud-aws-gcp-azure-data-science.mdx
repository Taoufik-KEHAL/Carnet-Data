Chaque fois qu'on me demande "quel cloud choisir pour la Data Science", ma première question
est "qu'est-ce que vous avez déjà". Le meilleur service managé sur le papier perd son avantage
si l'équipe doit en permanence faire transiter des données déjà stockées chez un concurrent.

## Les trois offres managées

AWS SageMaker reste le plus mature et le plus complet, avec un écosystème large — Pipelines,
Feature Store, Model Registry intégrés — au prix d'une prise en main plus lourde. Vertex AI
chez GCP propose une expérience plus unifiée, avec un vrai avantage pour les équipes déjà
orientées BigQuery, et une forte proposition côté IA générative. Azure Machine Learning est le
choix naturel des entreprises déjà dans l'écosystème Microsoft — Active Directory, Power BI —
avec une bonne intégration Synapse pour le Big Data.

| Critère | AWS | GCP | Azure |
|---|---|---|---|
| Maturité ML managé | Très élevée | Élevée | Élevée |
| Prise en main | Moyenne | Bonne | Bonne (écosystème MS) |
| Data warehouse phare | Redshift | BigQuery | Synapse Analytics |
| Point fort | Écosystème le plus large | Intégration analytics | Intégration entreprise |

## Le critère qu'on néglige

Le coût de transfert de données entre clouds (l'egress) et la friction opérationnelle de gérer
plusieurs fournisseurs dépassent presque toujours le gain de fonctionnalités d'un service
"meilleur sur le papier". Rester "cloud-agnostic" par principe, avec des outils compatibles
partout (Kubernetes, Terraform, MLflow auto-hébergé), a un coût réel : on renonce aux services
managés les plus performants de chaque plateforme pour une portabilité qu'on n'exploitera
probablement jamais.

Sauf contrainte réglementaire ou stratégique explicite, je recommande de choisir un cloud et
d'exploiter à fond son écosystème managé, plutôt que d'optimiser pour un changement de
fournisseur hypothétique.
